# Robust Object Detection in Satellite Images under Distribution Shift

**DG-Aug YOLO**: Domain-Generalized Augmentation for Satellite Object Detection under Climate Zone Shifts

> Based on: *Benchmarking Object Detectors under Real-World Distribution Shifts in Satellite Imagery* (Al-Emadi et al., 2025)

---

## Project Overview

Object detectors trained on satellite imagery from one climate zone (e.g., Tropical) suffer significant performance drops when deployed in other zones (e.g., Arid, Temperate). This project:

1. **Benchmarks** YOLOv8 under the RWDS-CZ framework (3 climate zones as domains)
2. **Proposes DG-Aug**: domain-generalized augmentation to improve OOD robustness
3. **Analyzes** Performance Drop (PD) and Harmonic Mean (H) across ID/OOD splits

### Dataset: RWDS-CZ-mini

| Domain | Climate Zone | xView Region |
|--------|-------------|--------------|
| CZ_A   | Tropical / Equatorial | Tropical regions |
| CZ_B   | Arid / Dry  | Desert regions |
| CZ_C   | Warm / Temperate | Temperate regions |

**8 classes**: Building, Small Car, Truck, Bus, Cargo Truck, Shipping Container, Vehicle Lot, Shed

### Model: YOLOv8s

- Pretrained on COCO, fine-tuned on RWDS-CZ
- Input: 640×640 (or 512×512 for weak GPU)
- Method name in report: **DG-Aug YOLO**

## Quick Start

### Streamlit video demo

Upload a satellite video, select one of the trained checkpoints in `runs/`,
and download the annotated result:

```bash
streamlit run streamlit_app.py
```

The app automatically discovers checkpoints matching
`runs/**/weights/best.pt`. Confidence, IoU, inference size, and CPU/GPU can be
configured from the sidebar.

### Step 1: Convert xView to YOLO format

```bash
python scripts/convert_to_yolo.py \
    --xview_img_dir /data/xview/train_images \
    --geojson       /data/xView_train.geojson \
    --koppen_raster /data/koppen/Beck_KG_V1_present_0p0083.tif \
    --out_dir       data \
    --tile_size     512 \
    --overlap       0.2
```

### Step 2: Create domain splits + config YAMLs

```bash
python scripts/split_domain.py \
    --data_dir data \
    --cfg_dir  configs \
    --min_samples 30
```

### Step 3: Run all experiments (recommended)

```bash
# Normal GPU (8GB+)
python scripts/run_experiments.py \
    --data_dir data \
    --model yolov8s.pt \
    --epochs 100 --imgsz 640 --batch 16 \
    --device 0

# Weak GPU (4GB or CPU)
python scripts/run_experiments.py \
    --data_dir data \
    --model yolov8n.pt \
    --epochs 50 --imgsz 512 --batch 8 \
    --device cpu
```

```bash
    --cfg configs/single_source_cz_a.yaml \

# Exp 2: Multi-source, test on CZ_C
python scripts/train_baseline.py \
    --cfg configs/multi_source_test_cz_c.yaml \
    --run_name multisrc_CZC --epochs 80

# Exp 3: DG-Aug, test on CZ_C (proposed method)
python scripts/train_dg_aug.py \
    --cfg configs/multi_source_test_cz_c.yaml \

python scripts/train_acs_yolo.py \
    --cfg configs/multi_source_test_cz_c.yaml \
    --run_name acsyolo_CZC --epochs 80 --warmup_epochs 10
```

### Evaluate cross-domain

```bash

python scripts/evaluate_domains.py \
    --weights results/runs/baseline_CZA/weights/best.pt \
    --data_dir data \

    --data_dir data \
    --id_zones CZ_A CZ_B \
    --ood_zones CZ_C \
    --run_name multisrc_CZC
```

## Metrics

| Metric | Formula | Meaning |
|--------|---------|---------|
| mAP50 | COCO AP@0.5 | Standard detection metric |
| mAP50:95 | COCO AP@0.5:0.95 | Strict multi-IoU metric |
| Performance Drop (PD) | `100 × (mAP_ID − mAP_OOD) / mAP_ID` | % degradation ID→OOD |
| Harmonic Mean (H) | `2 × mAP_ID × mAP_OOD / (mAP_ID + mAP_OOD)` | Joint ID/OOD score |

## DG-Aug: Method Description

DG-Aug adds augmentations that **simulate visual variations across climate zones**:

| Augmentation | Purpose |
|-------------|---------|
| `hsv_h=0.03, hsv_s=0.6, hsv_v=0.5` | Simulate different soil/vegetation colors |
| `degrees=10, flipud=0.1` | Overhead rotation invariance |
| `mosaic=1.0, mixup=0.1` | Exposure to diverse backgrounds |
| `GaussianBlur, GaussNoise` | Sensor noise simulation |
| `RandomFog` | Atmospheric haze (tropical/arid) |
| `CLAHE` | Contrast normalization |
| `CoarseDropout` | Cloud shadow simulation |

## ACS-YOLO: Adaptive Correspondence Scoring

ACS-YOLO adapts the idea from *Adaptive Correspondence Scoring for
Unsupervised Medical Image Registration* to supervised satellite detection.
Instead of trusting every training image equally, it estimates an image-level
reliability score from prediction consistency under style-only domain
perturbations.

Pipeline:

1. Warm up YOLO for `--warmup_epochs`.
2. Generate a climate-style augmented copy of each train image without moving
   boxes.
3. Compare predictions on original vs augmented images, with GT alignment as an
   additional residual signal.
4. Save `acs_scores.json` / `acs_scores.csv`.
5. Continue training with a custom ACS-weighted YOLO loss.

ACS is used only during training, so inference speed and model size stay the
same as the selected YOLO checkpoint.

Run a single ACS-YOLO experiment:

```bash
python scripts/train_acs_yolo.py \
    --cfg configs/multi_source_test_cz_c.yaml \
    --run_name exp4_acsyolo_test_CZC \
    --model yolov8s.pt \
    --epochs 80 \
    --warmup_epochs 10 \
    --device 0
```

Run ACS-YOLO through the full experiment runner:

```bash
python scripts/run_experiments.py --exp 4 --epochs 80 --acs_warmup_epochs 10
```
